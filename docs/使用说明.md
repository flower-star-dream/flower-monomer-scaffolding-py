## 1. 安装

建议在项目内创建虚拟环境：

```bash
python -m venv .venv
.venv\Scripts\activate

# 1) 框架依赖（本地 editable，默认方式；框架发布远程仓库后可改 pyproject 注释的 Git 方式）
pip install -e "f:\baseProject\flower-web-infrastructure[mysql,redis,migrate]"

# 2) 脚手架自身（业务包 + 开发依赖）
pip install -e ".[dev]"
```

> 框架最小能力说明见框架使用说明 1.x；本脚手架示例模块用到 MySQL/SQLite（ORM，`[mysql]`）、缓存（内存，核心）、密码加密（核心）、Alembic（`[migrate]`），生产接入 Redis 需 `[redis]`，以上 extras 一次装齐。

## 2. 配置说明

配置优先级：**环境变量 > `.env`（自动加载）> 项目根 `application.yml` > 框架默认 `application.default.yml`**。中间件 / 多租户 / AI 等特殊能力默认关闭，由 `application.yml` 显式启用。

**敏感配置（推荐 .env）**：复制 [`.env.example`](../.env.example) 为项目根 `.env` 并填写（`.env` 已被 `.gitignore` 忽略，不会提交仓库）。框架启动时自动加载项目根 `.env`，`application.yml` 中 `${ENV}` / `${ENV:default}` 占位符与环境变量覆盖均可读取；已存在的进程/容器环境变量优先（`.env` 不覆盖）。示例：

```bash
cp .env.example .env        # 然后编辑 .env 填写密码/密钥
```

```yaml
app:
  name: flower-monomer-scaffolding
  env: dev                       # 生产环境设置 APP_ENV=prod（环境变量优先）
  web:
    middlewares:
      security_headers: { enabled: true }
      auth:
        enabled: false           # 需启用统一鉴权时改为 true，并配置 JWT_SECRET_KEY 环境变量
        whitelist: ["/health", "/metrics", "/docs"]
      trace_id: {}
  cache:
    type: memory                 # memory / redis（生产推荐 redis）
  db:
    type: mysql                  # mysql / sqlite
    mysql:
      host: 127.0.0.1
      port: 3306
      database: flower_monomer
      username: root
      password: ${APP_DB_MYSQL_PASSWORD:}   # 敏感值经 .env/环境变量注入，缺省为空字符串
      use_ssl: false             # 本地开发无证书关闭 SSL；生产开启并配置 ssl_ca
  storage: { type: local, base_dir: ./data }
  mq: { type: memory }
  registry: { type: memory }
```

关键点：

- **MySQL SSL**：框架安全默认 `use_ssl: true`；本地无 SSL 证书的 MySQL 需显式 `use_ssl: false`，生产环境开启。
- **测试**：`tests/conftest.py` 将 db 组件替换为 SQLite 内存库（StaticPool），测试不依赖外部 MySQL。
- 已装配组件通过 `app.state.<name>` 访问（cache / db / storage / mq / registry / ai）。

## 4. 数据库变更管理

- **Alembic 为权威变更管理工具**（规范 §13.1），迁移脚本位于 `alembic/versions/`：

```bash
# 升级到最新版本（cwd=项目根；未设置 DATABASE_URL 时使用 alembic.ini 配置）
set DATABASE_URL=mysql+aiomysql://root:密码@127.0.0.1:3306/flower_monomer
alembic upgrade head

# 生成迁移（业务模型已在 alembic/env.py 导入注册到 Base.metadata）
alembic revision --autogenerate -m "add_xxx_table"

alembic history        # 迁移历史
alembic downgrade -1   # 回滚一个版本
alembic upgrade head --sql   # 离线生成 SQL（不连库）
```

- **手工 SQL 参考**（规范 §13.2）：基线 `db/init/`（只随大版本重建，禁止回改）、增量 `db/versions/`（`V{版本}-{模块}-{描述}-ddl/dml.sql` 成对，涉及存量数据语义变更必须提供幂等 DML；脚本头统一 `@Author / @Date / @Description`）。
- **初始数据**：`db/init/dml/001-user-init-dml.sql` 预置管理员账号（admin，密码 admin123，bcrypt 哈希），生产部署前必须修改默认密码或删除。

## 5. 示例模块说明（用户管理）

分层：`api/v1/user_controller.py`（接口）→ `service/user_service.py`（业务）→ `repository/user_repository.py`（数据）→ `model/user_model.py`（ORM）。

演示的能力：

| 能力 | 位置 | 说明 |
| ---- | ---- | ---- |
| 统一响应 `Result` / `PageResult` | controller | code + message + data 结构 |
| 统一错误码 `BizException` + `CommonErrorCode` | service | 用户不存在 COMMON_NOT_FOUND / 重名 COMMON_CONFLICT |
| ORM 会话 `db.orm_session()` | repository | 自动提交/回滚/关闭（规范 §10.6） |
| 密码加密 `PasswordEncoder` | service | bcrypt，72 字节截断 |
| 缓存防穿透 `set_empty` / `is_empty` | service | 空值占位 TTL ≤ 120s（规范 §8.2） |
| 分页 `PageQuery` / 深分页拒绝 | controller | 规范 §12.3 / S10-1 |
| 结构化日志 `get_logger` | service | 模块化 logger |

## 6. 扩展新业务模块

以新增"订单"模块为例：

1. `model/order_model.py`：定义实体（继承 `web_infra.Base`），并在 `model/__init__.py` 导出；
2. `schema/order_schema.py`：请求/响应 DTO；
3. `repository/order_repository.py`：统一走 `db.orm_session()`；
4. `service/order_service.py`：业务规则 + 错误码 + 日志；
5. `api/v1/order_controller.py`：注册到 `api/v1/__init__.py` 的 `api_router`；
6. 编写 Alembic 迁移（`alembic revision --autogenerate`）+ 配套基线/增量 SQL + 测试；
7. `main.py` 无需改动（`api_router` 已统一注册）。

> 常量规范：权限点 `AUTH_PERM_` 前缀（规范 §6.6）、缓存 Key `web:{module}:v1:{biz}`（规范 §5.7），禁止裸字符串。
> 注释规范：文件头统一 `@Author / @Date / @Description`，类定义上方注明类的中文名。

## 7. 测试与质量

```bash
.venv\Scripts\python.exe -m pytest                     # 全部测试
.venv\Scripts\python.exe -m pytest tests/test_user_module.py -q
.venv\Scripts\python.exe -m pytest --cov=app --cov-fail-under=70   # 覆盖率门禁（可选）
.venv\Scripts\pyright.exe                              # 静态类型检查（新增代码 0 错误）
```

测试约定：`tests/conftest.py` 提供 `db`（SQLite 内存库 + StaticPool）、`app`（替换 db 组件）、`client`（ASGI 直连）夹具；业务模块测试不依赖外部 MySQL。

## 8. 部署（Docker / CI）

**Docker**：业务镜像基于框架基础镜像：

```bash
docker build -t flower-web-infrastructure:latest f:\baseProject\flower-web-infrastructure
docker build -t flower-monomer-scaffolding:latest .
docker run -d -p 8000:8000 -v "$(pwd)/application.yml:/app/application.yml" flower-monomer-scaffolding:latest
```

**CI**（`.github/workflows/ci.yml`）：推送 main / PR 时执行 pyright 静态检查 + pytest 单元测试。框架依赖采用"检出框架仓库 + editable 安装"方式；框架发布远程仓库后改 pyproject 的 Git 依赖并简化本文件（`<org>` 替换为实际组织）。
